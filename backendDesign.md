# Argus-IDS Backend Design

## 1. Overview

The `backend/` package is a FastAPI backend for Argus-IDS that serves intrusion detection, alert history, health, explainability, threshold, and simulation endpoints for the Streamlit frontend. It depends on saved model artifacts under `backend/model/`, request/response contracts in Pydantic schemas, scikit-learn/XGBoost-style estimators loaded with `joblib`, pandas/numpy preprocessing, SHAP explanations, and an optional Discord webhook configured by environment variables.

### `backend/api/routes.py`

- Purpose: Defines API handlers, lazy-loads singleton artifacts, converts packets into model-ready vectors, writes in-memory logs, and orchestrates prediction/explanation/simulation flows.
- Public functions / classes:
  - `_load_resources() -> None`: loads model/test/explainer singletons once; raises `RuntimeError("One or more model artefacts failed to load — check backend/model/.")` when required artifacts are `None`, or `RuntimeError("Model metadata indicates PCA was used, but pca.pkl is missing.")`.
  - `_build_packet(request_features: dict[str, float]) -> pd.Series`: orders raw fields by `_features`, fills missing values with `0.0`, scales with `_scaler`, optionally transforms with `_pca`, and returns a model-feature `Series`; raises `RuntimeError("Model artefacts are not loaded.")`.
  - `health() -> dict`: `GET /health`; returns `{"status": "ok"}`.
  - `predict(request: PredictRequest) -> PredictResponse`: `POST /predict`; runs the full prediction pipeline, appends `_alert_log`, and dispatches on `"HIGH"` or `"ANOMALY"`; raises `HTTPException(503)` when resource loading fails.
  - `explain(request: ExplainRequest) -> ExplainResponse`: `POST /explain`; returns SHAP contributions without dispatching alerts; raises `HTTPException(503)` when resource loading fails.
  - `threshold_metrics(threshold: float = 0.5) -> ThresholdMetricsResponse`: `GET /model/threshold`; computes confusion matrix and metrics; raises `HTTPException(503)` for missing threshold artifacts and `HTTPException(400)` for threshold outside `0.0..1.0`.
  - `simulate(request: SimulateRequest) -> SimulateResponse`: `POST /simulate`; runs a sliding-window simulation; raises `HTTPException(503)` when resource loading fails.
  - `simulations() -> SimulationsResponse`: `GET /simulations`; returns recent simulations.
  - `predict_random() -> PredictRandomResponse`: `POST /predict/random`; selects a random test packet and runs prediction; raises `HTTPException(503)` when resource loading fails.
  - `alerts() -> AlertsResponse`: `GET /alerts`; returns recent alert entries.
- Key constants or config values: `_alert_log: Deque[AlertEntry] = deque(maxlen=50)`; `_simulation_log: Deque[SimulateResponse] = deque(maxlen=50)`; singleton variables `_ensemble`, `_iso_forest`, `_scaler`, `_features`, `_model_features`, `_pca`, `_metadata`, `_y_test`, `_explainer`, `_X_test`, `_X_test_raw`; alert trigger check `result.severity in ("HIGH", "ANOMALY")`; SHAP `top_n=5`; dispatched SHAP slice `shap_dicts[:3]`.
- Dependencies: `collections.deque`; `datetime`; `typing.Deque`; `numpy`; `pandas`; `fastapi.APIRouter`; `fastapi.HTTPException`; schemas from `backend.api.schemas`; loaders from `backend.core.model`; simulation helpers from `backend.core.simulation`; `sklearn.metrics.confusion_matrix`, `f1_score`, `precision_score`, `recall_score`; `backend.services.alert_dispatcher.dispatch_alert`; SHAP helpers from `backend.services.SHAP_explainer`.
- Must NOT do: train models, import `backend.core.data` for request-time preprocessing, import benchmark artifacts directly, persist alert logs to disk, or own Pydantic schema definitions.

### `backend/core/data.py`

- Purpose: Provides training-time dataset loading and preprocessing helpers in the fixed training order: cleaning, label encoding, stratified split, train-only scaling, train-only SMOTE, optional PCA.
- Public functions / classes:
  - `load_dataset(filepath: str) -> pd.DataFrame`: loads a CSV with pandas, strips column names, replaces infinities with NaN, drops NaN rows, and drops `_DROP_COLS` if present; raises pandas file/parse exceptions from `pd.read_csv`.
  - `split_dataset(df: pd.DataFrame, feature_names: list[str], use_pca: bool = False, pca_components: int = 30) -> tuple[pd.DataFrame, pd.DataFrame, pd.Series, pd.Series]`: encodes `Label`, splits train/test with stratification, fits `MinMaxScaler` on train only, saves `scaler.pkl`, applies SMOTE to train only, optionally applies PCA, and returns train/test matrices and labels; may raise `KeyError`, scikit-learn validation errors, or filesystem/joblib errors.
- Key constants or config values: `_DROP_COLS = ["Flow ID", "Source IP", "Destination IP", "Timestamp"]`; `_LABEL_COL = "Label"`; `_MODEL_DIR = os.environ.get("ARGUS_MODEL_DIR", "backend/model")`; `test_size=0.2`; `random_state=42`; default `use_pca=False`; default `pca_components=30`; `SMOTE(random_state=42)`.
- Dependencies: `os`; `numpy`; `pandas`; `sklearn.model_selection.train_test_split`; `sklearn.preprocessing.MinMaxScaler`; `sklearn.decomposition.PCA`; `imblearn.over_sampling.SMOTE`; local imports inside `split_dataset`: `joblib`, `os`.
- Must NOT do: serve requests, create FastAPI dependencies, refit scalers during inference, dispatch alerts, or override route-time schema validation.

### `backend/core/decision.py`

- Purpose: Converts ensemble label/confidence plus Isolation Forest label/score into a `DecisionResult` with prediction and severity.
- Public functions / classes:
  - `Severity(str, Enum)`: enum values `LOW`, `MEDIUM`, `HIGH`, `ANOMALY`.
  - `DecisionResult`: dataclass with `prediction: str`, `severity: Severity`, `confidence: float`, `anomaly_score: float`, `is_anomaly: bool`.
  - `decide(ensemble_label: int, ensemble_confidence: float, iso_label: int, iso_score: float) -> DecisionResult`: applies Section 6 logic and rounds confidence/score to 4 decimals; does not explicitly raise.
- Key constants or config values: attack label is `ensemble_label == 1`; benign label is `ensemble_label == 0`; anomaly flag is `iso_label == -1`; high threshold is `ensemble_confidence >= 0.75`.
- Dependencies: `dataclasses.dataclass`; `enum.Enum`.
- Must NOT do: call `predict_proba`, call `iso_forest.predict`, read request bodies, dispatch alerts, or mutate logs.

### `backend/core/evaluation.py`

- Purpose: Provides offline benchmarking metrics for fitted classifiers.
- Public functions / classes:

- Key constants or config values: `target_names=["BENIGN", "ATTACK"]`; calibration bins `n_bins=10`; rounded `roc_auc` and `pr_auc` to 4 decimals.
- Dependencies: `numpy`; `pandas`; `sklearn.metrics.confusion_matrix`, `roc_curve`, `auc`, `precision_recall_curve`, `classification_report`; `sklearn.calibration.calibration_curve`.
- Must NOT do: define API endpoints, alter production decision thresholds, or load model artifacts by path.

### `backend/core/simulation.py`

- Purpose: Runs single-packet prediction helpers and window-level simulations against already scaled test data.
- Public functions / classes:

- Key constants or config values: `window_size=50`; `threshold=0.6`; per-packet attack probability threshold `0.5`; window severity thresholds `mean_risk < 0.4`, `< 0.6`, else `HIGH`.
- Dependencies: `numpy`; `pandas`; `datetime.datetime`; `backend.core.decision.decide`; `backend.core.decision.DecisionResult`.
- Must NOT do: scale raw `/predict` requests in current API flow, dispatch Discord alerts, own API schemas, or mutate `_alert_log`.

## 4. API Endpoints

### `POST /predict`

- Request schema: `PredictRequest`

```json
{
  "features": {
    "Flow Duration": 123456,
    "Total Fwd Packets": 10
  }
}
```

| Field | Type | Required? | Notes |
|---|---|---:|---|
| `features` | `dict[str, Any]` | Yes | Values are converted with `float(request_features.get(f, 0.0))` in `routes._build_packet`. |

- Response schema: `PredictResponse`

```json
{
  "prediction": "ATTACK",
  "severity": "HIGH",
  "anomaly_score": -0.1234,
  "confidence": 0.9812,
  "shap_top_features": [
    {"feature": "Flow Duration", "impact": 0.1452}
  ],
  "timestamp": "2026-05-23T10:30:00.000000+00:00"
}
```

- Actual work owner: `routes.predict` orchestrates; `routes._build_packet` scales; `simulation.predict_packet` calls models; `decision.decide` assigns severity; `SHAP_explainer` computes impacts; `alert_dispatcher.dispatch_alert` sends webhooks.
- Error responses:
  - `422 Unprocessable Entity`: FastAPI/Pydantic validation error when request body does not match `PredictRequest`.
  - `503 Service Unavailable`: `{"detail": "<RuntimeError message>"}` when `_load_resources()` fails.
  - `500 Internal Server Error`: uncaught estimator, SHAP, pandas, or conversion exceptions.

### `GET /alerts`

- Request schema: no request body.
- Response schema: `AlertsResponse`

```json
{
  "alerts": [
    {
      "timestamp": "2026-05-23T10:30:00.000000+00:00",
      "prediction": "ATTACK",
      "severity": "HIGH",
      "confidence": 0.9812,
      "anomaly_score": -0.1234,
      "shap_top_features": [
        {"feature": "Flow Duration", "impact": 0.1452}
      ]
    }
  ],
  "total": 1
}
```

- Actual work owner: `routes.alerts`; data source is in-memory `_alert_log` capped at 50 entries.
- Error responses:
  - No explicit application errors.
  - `500 Internal Server Error`: uncaught serialization/runtime exceptions.

- Request schema: no request body.
- Response schema:

```json
{
  "status": "ok"

```

## 5. Detection Pipeline (Data Flow)

| Step | Source-requested step | Implemented owner | Actual behavior |
|---:|---|---|---|
| 1 | `routes.py` receives request | `backend/api/routes.py::predict` | FastAPI parses JSON into `PredictRequest`. |
| 2 | `schemas.py` validates | `backend/api/schemas.py::PredictRequest` | Requires `features`; values are `Any`, so numeric conversion happens later. |
| 3 | `model.py` loads `ensemble_model.pkl` + `rf_features.pkl` | `routes._load_resources`, `core.model` loaders | Lazy-loads ensemble, iso forest, scaler, features, model features, metadata, y_test, X_test, X_test_raw, and SHAP explainer once. |
| 4 | `data.py` preprocessing in fixed training order | Training owner: `core/data.py`; request owner: `routes._build_packet` | `data.py` owns training preprocessing; per-request code uses saved `_features`, `_scaler`, optional `_pca`, and `_model_features`. |
| 5 | Ensemble `predict_proba` -> calibrated confidence | `core/simulation.py::predict_packet` | Builds a one-row DataFrame, calls `_ensemble.predict_proba`, chooses `np.argmax(proba)`, and uses that probability as confidence. |
| 6 | `iso_forest.pkl` anomaly score | `core/simulation.py::predict_packet` | Calls `_iso_forest.predict(packet_df)[0]` and `_iso_forest.score_samples(packet_df)[0]`. |
| 7 | `decision.py` severity logic | `core/decision.py::decide` | Applies Section 6 logic and returns `DecisionResult`. |
| 8 | `SHAP_explainer.py` top-N impacts | `services/SHAP_explainer.py` | `generate_shap_analysis(..., top_n=5)` returns vector; `get_top_shap_features(..., top_n=5)` formats response. |
| 9 | `alert_dispatcher.py` fires if `HIGH` or `ANOMALY` | `api/routes.py`, `services/alert_dispatcher.py` | Route checks `result.severity in ("HIGH", "ANOMALY")`, then dispatcher independently checks `_ALERT_SEVERITIES`. |
| 10 | Response assembled and returned | `backend/api/routes.py::predict` | Appends `AlertEntry` to `_alert_log`, returns `PredictResponse`. |

Current implementation note: `load_model_features()`, `load_metadata()`, and `load_y_test()` are required by `_load_resources()`, and the current `backend/model/` folder contains `model_features.pkl`, `metadata.json`, and `y_test.pkl`. `pca.pkl` is absent, but current metadata has `ARGUS_USE_PCA: false`, so `_load_resources()` does not require PCA.

## 6. Decision Engine Logic

| Condition in `decide` | Exact code variables | Threshold values | `prediction` | `severity` |
|---|---|---|---|---|
| `ensemble_label == 0` and `iso_label == -1` | `ensemble_label`, `is_anomaly: bool = iso_label == -1` | No numeric threshold | `"BENIGN"` | `Severity.ANOMALY` |
| `ensemble_label == 0` and `iso_label != -1` | `ensemble_label`, `is_anomaly` | No numeric threshold | `"BENIGN"` | `Severity.LOW` |
| `ensemble_label == 1` and `ensemble_confidence >= 0.75` | `ensemble_label`, `ensemble_confidence` | `0.75` | `"ATTACK"` | `Severity.HIGH` |
| `ensemble_label == 1` and `ensemble_confidence < 0.75` | `ensemble_label`, `ensemble_confidence` | `0.75` | `"ATTACK"` | `Severity.MEDIUM` |

Returned values are rounded as `confidence=round(ensemble_confidence, 4)` and `anomaly_score=round(iso_score, 4)`.

Chart artifacts present but not loaded by the backend code: `confusion_matrix.png`, `roc_curve.png`, `precision_recall_curve.png`, and `calibration_curve.png`.

There are no `.pkl` files loaded at FastAPI application startup. They are loaded lazily by `routes._load_resources()` on the first call to endpoints that need model resources and then reused via module-level singletons. No artifact is intentionally loaded per request after the singleton cache is populated.

Missing required artifact error path: individual `load_*` functions return `None` when the file path does not exist; `_load_resources()` raises `RuntimeError("One or more model artefacts failed to load — check backend/model/.")`; route handlers convert that into `HTTPException(status_code=503, detail=str(exc))`.

Rule: `ensemble_model.pkl` is the ONLY classifier model used at prediction time. `rf_model.pkl` and `xgb_model.pkl` are benchmarking artifacts and are never loaded by `backend/api/routes.py` or `backend/core/model.py` inference flow.

## 9. Alert Dispatcher

- Trigger conditions: route code and dispatcher both treat `"HIGH"` and `"ANOMALY"` as alert severities. Dispatcher constant is `_ALERT_SEVERITIES = frozenset({"HIGH", "ANOMALY"})`.
- Env var name: `ARGUS_DISCORD_WEBHOOK_URL`.
- Payload sent to Discord:

```json
{
  "content": "ARGUS-IDS ALERT content string with severity, timestamp, confidence, anomaly score, and top SHAP features"
}
```

- Webhook success condition: `requests.post(_DISCORD_WEBHOOK_URL, json=payload, timeout=5)` returns HTTP status `204`.
- Webhook failure behavior: silent failure. `dispatch_alert` returns `False` for unalertable severities, missing webhook URL, non-`204` response, or `requests.RequestException`; it does not raise.

## 11. Error Handling Patterns

- Validation errors: FastAPI/Pydantic returns `422 Unprocessable Entity` with the default body shape containing `detail`, where `detail` is a list of validation error objects with fields such as `type`, `loc`, `msg`, and `input`.
- Expected resource errors: endpoints that call `_load_resources()` catch `RuntimeError` and return `HTTPException(status_code=503, detail=str(exc))`.
- Endpoint-specific validation: `threshold_metrics` returns `400` with `{"detail": "threshold must be between 0.0 and 1.0"}` when `threshold < 0.0 or threshold > 1.0`.
- Unexpected exceptions: no global exception handler is defined in backend source; FastAPI will return its default `500 Internal Server Error` response.
- Logging approach: NOT YET IMPLEMENTED. No `logging` import, configured logger, log levels, structured logs, or explicit exception logging exists in `backend/`.

## 12. Frontend Contract (For Frontend Developer)

- Base URL env var name: Vite frontend uses `VITE_ARGUS_BACKEND_URL`, defaulting to `http://localhost:8000`.
- `/health` polling behavior: `GET {backend_url}/health` with timeout `5`; healthy response is HTTP `200` plus JSON `{"status": "ok"}`.
- Exact `/predict` request shape: send JSON `{"features": {"<feature name>": <numeric value>, "...": <numeric value>}}`; missing known features are filled with `0.0`; non-float-convertible values can cause server errors.
- Exact `/predict` response shape: see Section 4 `POST /predict`; fields are `prediction`, `severity`, `anomaly_score`, `confidence`, `shap_top_features`, and `timestamp`.
- Exact `/alerts` response shape: see Section 4 `GET /alerts`; fields are `alerts` and `total`; `alerts` contains at most 50 entries, most recent first.
- CORS configuration: `allow_origins` comes from `ARGUS_ALLOWED_ORIGINS` split on commas, default `["http://localhost:5173"]`; `allow_methods=["GET", "POST"]`; `allow_headers=["Content-Type"]`.

## 13. What Is Out of Scope for the Backend

- No direct model imports from frontend code; the frontend must call HTTP endpoints.
- No CNN or LSTM inference path; production prediction uses `ensemble_model.pkl` plus `iso_forest.pkl`.
- No live packet capture; inputs are JSON features or saved test-set simulation/random packets.
- No email alerts; only optional Discord webhook dispatch exists.
- No Docker requirement is implemented or required by the backend source.
- No training through API endpoints; training-time helpers live in `core/data.py` and artifacts are loaded from disk.
- No persistent database for alerts or simulations; logs are in-memory deques capped at 50.
- No authentication or authorization layer.
- No backend-owned frontend rendering; UI belongs to `frontend/`.
